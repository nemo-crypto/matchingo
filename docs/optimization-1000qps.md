# 撮合边界与性能优化验收

## 范围与兼容性

本项目是内存撮合 Go 库，无 HTTP/RPC 服务。本次 QPS 指 `Process` 或 `CancelOrder` 的调用次数；不包含网络、认证、余额校验、持久化、结算。结果仅代表本机 Apple M5 / macOS arm64 / Go 1.25.11，不能作为线上硬件的容量保证。

原 `OrderBook` 保留串行、可变对象 API。新增可选 `ConcurrentOrderBook`：同一交易对串行撮合，入参及返回订单复制，深度返回独立快照；按交易对创建多个实例实现分片。调用方不得在提交期间并发修改同一个入参。未引入后台协程、依赖或新的服务层。

价格优先、同价 FIFO、止损按精确成交价格触发并转为挂单、未成交限价单的 `Done.Left` 原有约定均保留。构造函数对非法数量/价格仍 panic，`Process` 返回 error。

## 已修复边界

- FOK 预检查会将 OCO 两腿重复算作可用流动性，实际撮合时取消另一腿导致部分成交。存在可能影响本次成交的 OCO 或止损时，在隔离副本中沿真实撮合路径模拟，验证足额成交后才改变原簿；无 OCO 保留原快速预检查。
- `int64` 定点乘除中间溢出：采用 128 位中间值；无法表示的市价估值返回 `ErrArithmeticOverflow`，不改变订单簿。
- 报价金额市价单的微量成交可能支出为零：每次同价队列处理的成交基础币总量，向上取整至一个报价最小单位。支出不会超过预算。`CalculateMarketPrice` 仍向下截断估值，不承诺等于精确可执行报价；手续费和逐笔结算须由接入层定义。
- 防止档位总量及 FOK 累加溢出：累计双边及未触发止损的基础币原始数量。新限价/止损单全量加上已挂数量超过 `MaxInt64` 时，在撮合前返回 `ErrBookCapacity`。这是保守限额，即使新单本可立即成交也可能被拒绝；市价单不预占挂单容量。
- 空订单 ID、自引用 OCO 在修改前拒绝；空队列 `First()` 返回 nil。
- `SetDecimalFraction` 仅接受 0..10，非法值 panic 且不改变设置。精度是依赖库全局变量，必须在创建价格/订单、启动并发前一次性配置，不能运行中更改。

## 性能调整

止损价格索引改用定点数键，消除热路径字符串转换。`Depth` 直接遍历价格映射并预分配返回 map，避免逐档树搜索；输出仍为无序快照。

新增独立生命周期基准，不复用全局簿，检查错误并准确区分每轮生命周期与操作次数。`make bench` 使用新基准；历史 BenchmarkLimitOrders 与 README 历史机器数字不作本次验收依据。`make test` 不再隐式格式化整个仓库。

## 可复现命令

```sh
go test ./... -count=1
go test -race ./... -count=1
go vet ./...
go test . -run '^$' -fuzz FuzzMulDiv -fuzztime=10s
go test ./tests -run '^$' -bench 'BenchmarkEngine|BenchmarkStopLookup|BenchmarkDepthSnapshot|BenchmarkConcurrentBook|BenchmarkFOKWithOCO' -benchmem -benchtime=200ms -count=3
go run ./cmd/loadtest -rate 1000 -duration 30s -workers 8
go run ./cmd/loadtest -rate 1000 -duration 30s -workers 8 -depth 1000 -oco
go run ./cmd/loadtest -rate 10000 -duration 30s -workers 8 -depth 1000
```

压测固定有界 worker/队列和延迟直方图；按绝对时间计划投放，不因阻塞丢弃样本。每个生命周期有两次操作，四类各占 25%：挂单撤单、挂单基础币市价成交、挂单报价金额成交、挂单 FOK 成交。延迟为整个两操作生命周期，包含生产者迟到、队列等待；不是单次撮合的纯 CPU 延迟。直方图超过 1s 的分位数仅报告 `>1s`，最大值保留实际值。结束等待清空队列，排空时间计入吞吐；失败、意外残留或低于目标 99% 返回非零。预填充订单不计吞吐，结束检查其数量未被误消耗并撤销。

## 适用边界

原始 `OrderBook` / `OrderSide` / `OrderQueue` 及公开 `Stop`、`OCO` 仍是低层可变 API，不允许绕过 `Process`/`CancelOrder` 修改存量对象；容量检查不能保护自行修改这些结构的调用方。金额输入转换也须在表示范围内；本次没有替换 fpdecimal 的所有公开转换函数。

复杂 OCO/FOK 的隔离模拟需要复制订单簿及待取消标记，成本随簿大小增长；密集同价队列任意位置撤单仍有线性扫描。不存在“所有订单分布均最佳”的保证。迟到 OCO 标记保持原生命周期，不擅自过期，长期运行应由接入方管理 ID 生命周期和资源限额。压测不代表持久化故障恢复、资产安全、极端深簿的延迟 SLA 或生产结算验收。

## 本机实测结果

### 微基准

同机、每项 200ms、重复三次取中位数。时间单位 ns，Engine 为完整生命周期（含挂单和成交/撤单）；并非单笔成交时间。

| 场景 | 修改前 ns/op | 修改后 ns/op | 修改前 → 后 allocs/op |
| --- | ---: | ---: | ---: |
| 基础币撮合 | 267.8 | 260.0 | 13 → 12 |
| 挂单/撤单 | 150.1 | 160.5 | 6 → 6 |
| 报价金额撮合 | 265.9 | 267.3 | 13 → 12 |
| 止损完整生命周期 | 583.0 | 626.6 | 26 → 24 |
| 普通 FOK | 271.1 | 273.4 | 13 → 12 |
| 扫 100 档 | 31,170 | 32,097 | 811 → 711 |
| 空止损簿查询 | 14.95 | 1.528 | 1 → 0 |
| 10,000 止损价位未命中查询 | 20.61 | 3.297 | 1 → 0 |
| 1000 档深度快照 | 108,563 | 48,172 | 2024 → 2008 |

深度快照分配从约 176,395 降至 98,112 B/op（约 -44%），耗时约 -56%。新增校验及总量维护有成本：挂单/撤单约 +7%、止损生命周期约 +7.5%，没有将这些回退隐藏为全面提速。三次短测不能证明细小差异的统计显著性。

并发包装器挂单/撤单基准中位数 394.8ns/生命周期，约 506 万操作/秒；这是短时微基准，不是持续服务吞吐。OCO FOK 拒单隔离模拟：10 条挂单约 1.713μs、5200B；1000 条约 126.099μs、364482B。修复前会错误成交，不能用其速度作为等价性能对照。

### 正确性验证

全量单测、竞争检测、vet 均通过。随机混合测试使用 8 个固定种子 × 3000 操作，每步检查价格/订单/止损索引、数量、深度、OCO 计数和 FOK 原子性。算术模糊测试用 `big.Int` 作独立参考，10 秒执行 4,374,590 组输入通过，覆盖乘除溢出、零除数及向上舍入。另覆盖精度 0..10、买卖两个方向、拒绝非法精度且不改变全局配置、容量拒绝无副作用和释放容量、并发输入/输出隔离。

### 持续负载（每轮 30 秒、8 个 worker）

| 目标操作/秒 | 预填背景 | 完成操作 | 实际操作/秒 | 生命周期 P50 / P95 / P99 | 最大延迟 | 错误 |
| ---: | --- | ---: | ---: | --- | ---: | ---: |
| 1000 | 无 | 30,000 | 999.99 | 245 / 269 / 309 μs | 6.563ms | 0 |
| 1000 | 1000 档，含 OCO | 30,000 | 1000.00 | 249 / 1508 / 2121 μs | 9.576ms | 0 |
| 10,000 | 1000 档，无 OCO | 300,000 | 9999.99 | 35 / 47 / 78 μs | 16.156ms | 0 |

三个命令均退出 0，通过背景订单数量和最终清空检查。边界时间误差产生 999.99/9999.99；验收阈值明确为目标的 99%。尾延迟包含操作系统调度，不能将较高投放速率下更小的调度延迟解读为撮合算法加速。1000 档含 OCO 一轮验证了复杂预检查成本；未宣称所有簿深或无界 OCO 标记下均满足该速率。

## 第二轮：OCO/FOK 副本分配优化

保留完整模拟撮合算法及 FIFO 语义，将逐订单堆分配改为单一订单数组，预分配订单和 OCO 索引；按价格 map 复制，避免构造有序价格切片。同价位仍按原队列顺序复制，副本仍通过价格树撮合。

针对第二轮修改前后重新运行 `BenchmarkFOKWithOCO`，各 200ms × 3 次，中位数：

| 预存订单 | 本轮修改前 ns/op | 修改后 ns/op | B/op 前 → 后 | allocs/op 前 → 后 |
| ---: | ---: | ---: | --- | --- |
| 10 | 1660 | 1522 | 5200 → 5096 | 62 → 54 |
| 1000 | 116129 | 73815 | 364482 → 305522 | 2077 → 1064 |

1000 单场景耗时约降低 36%，分配次数约降低 49%。以上是本轮重新测量，前文为首轮历史结果，不能混用不同轮次的小幅波动。复杂 FOK 仍随订单簿和 OCO 标记规模增长，不声称已消除其复杂度。

新增回归：失败 FOK 的模拟过程会成交第一腿、撤销第二腿并激活止损，连续执行三次后，原订单指针、数量、止损类型、待取消标记及所有索引必须保持一致。

新增 `BenchmarkDenseLevelCancel`：10,000 条同价订单，使用固定种子随机选择 ID 撤销并重新挂单。必须随机采样，固定遍历一个排列在预热后会退化成每次撤队首，不能代表随机撤单。

第二轮持续压测复跑：`go run ./cmd/loadtest -rate 1000 -duration 30s -workers 8 -depth 1000 -oco`，30,000 次操作全部成功，1000.00 操作/秒，生命周期 P50/P95/P99 为 249/1363/1729μs，最大 11.762ms，最终残留检查通过。尾延迟存在系统调度波动，不能据单轮结果承诺硬实时上界。

随机密集撤单基准：中位 11,224ns/撤单＋重挂生命周期、256B、2 次分配，约 178,184 操作/秒。该数据是微基准，不是持续负载；保留现有公开 deque API，未为追求常数时间撤单破坏接口。顺序队首撤单与随机撤单不可混作同一性能指标。

第二轮全量测试、`go test -race ./... -count=1`、`go vet ./...`、格式与 `git diff --check` 检查通过。未提交、推送或部署。

## 第三轮：避免无关 OCO 引发全簿复制

之前只要簿中存在任意 OCO，FOK 都会复制整个簿，即使 OCO 价格超出限价、不参与本次成交。现在按对手盘价格优先、同价 FIFO 扫描足额成交所需的订单前缀：前缀内没有 OCO，且触及价格没有待激活止损时，可以证明成交过程中没有取消其他流动性的来源，直接使用该可成交性结果。前缀包含 OCO 或触及价格可能激活止损时仍执行完整隔离模拟。买卖方向、限价、数量和挂单均不改变；入单待取消 OCO 标记仍由 `Process` 原有调用链先处理。

新增 `fok_test.go` 覆盖买卖两侧的无关 OCO、同价后续 OCO、实际消费 OCO、触发止损、不触发止损、数量不足、价格越界及跨价位成交。随机混合测试增加与完整模拟结果交叉检查，验证快速判断足额时完整模拟也必须足额。

本轮修改前后 `BenchmarkFOKUnrelatedOCO`，每项 200ms × 3，中位数；每轮包含挂单和 FOK 成交：

| 背景价位数 | 修改前 ns/op | 修改后 ns/op | B/op 前 → 后 | allocs/op 前 → 后 |
| ---: | ---: | ---: | --- | --- |
| 1000 | 216167 | 395.3 | 534631 → 928 | 4066 → 12 |
| 10000 | 3146715 | 432.3 | 5038922 → 928 | 40153 → 12 |

这只说明无关 OCO 不再触发全簿复制，并不代表涉及 OCO 的订单也获得同等提速。真实 OCO 路径的 1000 单基准中位数为 75,478ns、305522B、1064 次分配，与第二轮约 73,815ns 同量级，保留正确性模拟成本。

第三轮 `go test ./... -count=1`、`go test -race ./... -count=1`、`go vet ./...` 均通过。复现性能命令：

```sh
go test ./tests -run '^$' -bench 'BenchmarkFOKUnrelatedOCO|BenchmarkFOKWithOCO' -benchmem -benchtime=200ms -count=3
go run ./cmd/loadtest -rate 1000 -duration 60s -workers 8 -depth 10000 -oco
```

注意当前压测 `-oco` 将背景价位的两张订单关联，属于无关 OCO 场景；真实参与成交的 OCO 由对应边界测试和 `BenchmarkFOKWithOCO` 覆盖。不能把它写成持续复杂 OCO 成交的吞吐证明。

第三轮 60 秒深簿持续压测结果：10,000 档背景订单，8 个 worker，完成 60,000/60,000 次操作，实际 1000.00 操作/秒、错误 0；生命周期 P50/P95/P99 = 246/272/344μs，最大 9.871ms。背景订单数量及最终清空检查通过，命令退出 0。此处 OCO 位于不参与成交的背景价位，持续负载涵盖挂单撤单、基础币市价、报价金额市价和普通 FOK。
